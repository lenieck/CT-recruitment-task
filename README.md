# Alcohol brands taxonomy for URL classification
## About the project

The aim of this project is to create a taxonomy of alcohol brands that can be recognised in web traffic data. For each brand, a keyword query was prepared in the JSON format used by the URL keywords tool, and then it was checked in the estimator. A brand was included in the final list only if the estimator found at least one URL for it and the returned URLs were related to alcohol.

The final result is the file `data/kleniec.json`, which contains 126 queries.

## Summary of results

| Step | Number of brands |
|---|---|
| Scraped list | 1071 |
| After cleaning and removing duplicates | 1069 |
| At least one URL found by the estimator | 127 |
| No URL found | 942 |
| Rejected after manual review | 1 |
| Final list | 126 |

The 127 brands with URLs returned 313 unique URLs in total.

## What I focused on

The main priorities were automation and the correctness of the URLs, and not the length of the final list. Every brand goes through the same steps and receives a query built in the same way, so the pipeline can be used for a much longer list of brands without any changes. The only manual step is the review of the returned URLs at the end. As a consequence, the final list is relatively short, which is discussed in the section about limitations.

## Method
### Collecting the brands
The brand names were scraped from [boozesip.com](https://boozesip.com/brands/) and saved in `data/brands_raw.csv`.

### Cleaning the data

The script `data_preparation.py` converts all brand names to lowercase, replaces different types of apostrophes with a standard one, removes text in parentheses, removes accents (e.g., "crème" becomes "creme"), removes extra whitespace, removes empty strings, and drops duplicate brand names.

The names were converted to lowercase and accents were removed to make them consistent with the URL format. Text in parentheses was removed because it often contains additional information, such as specific product, rather than part of the brand name. Apostrophes were standardized because the rule for handling names ending in `'s`, described in the next section, depends on a consistent apostrophe format.

The result is the file `data/brands_cleaned.csv` with one column named `brand`. After cleaning, 1069 brands remained. The cleaned name is also used as the `id` of the query.

### Building the queries

The script `query_generator.py` builds the queries and saves them in the file `data/queries.json`.
The brand name is placed in `required` and a dictionary of words related to alcohol is placed in `optional` with `optionalThreshold` equal to 1. As a result, a URL is matched only if it contains the brand name and at least one word from the dictionary. Without the dictionary, many brand names match pages that are not related to alcohol, which is shown in the latter analysis.

The dictionary was generated by an AI assistant. It was asked for a list of words related to alcohol and returned types of alcohol with their plural forms and words such as `distillery`, `brewery` or `beer`. After that, a few words were added manually: some of them after the analysis of the initial results (for example `veviski`) and some on the basis of my own ideas. All of the words from dictionary use mode `m`, which means that a word has to appear in the URL separately, so for example `gin` does not match `login`.

The `required` part is created from the cleaned name according to the following rules:

- Words consist of lowercase letters (`a-z`), digits (`0-9`) and apostrophes. Any other character (e.g., a space, `&`, `.`, `/`) separates the words.
- Words are joined with hyphens (`-`), which match any non-alphanumeric character in URLs. For example, `absolut-vodka` matches `absolut-vodka`, `absolut/vodka` and `absolut%20vodka`.
- Apostrophes inside words are removed (e.g., `d'usse` becomes `dusse`) because they are usually not present in URLs.
- If a word ends in `'s`, the part before the ending becomes a separate keyword in mode `c` (contains), and the ending `'s` is dropped. In a URL, such a name can appear as `jack-daniels` or `jack-daniel-s`. Mode `m` would not match `daniels` for the keyword `daniel`. Any remaining words are placed in another keyword in mode `m`.
- If two names produce identical `required` lists, only the first query is kept.

| Cleaned name | `required` |
|---|---|
| `absolut vodka` | `absolut-vodka` (m) |
| `bib & tucker` | `bib-tucker` (m) |
| `d'usse` | `dusse` (m) |
| `jack daniel's` | `jack-daniel` (c) |
| `seagram's 7` | `seagram` (c) and `7` (m) |

### Running the estimator

The script `query_executor.py` sends each query (without the `id`) to the estimator. The response contains URLs from five sources. The script combines them and removes duplicates (the prefixes `http://`, `https://` and `www.` are ignored when comparing URLs). Two files are created:

- `data/review_urls.csv` with the columns `brand`, `count` (the number of unique URLs), `urls`, `source1` to `source5` (the number of URLs returned by each source) and an empty column `decision`, which is used in the manual review,
- `data/urls_not_found.csv` with the brands for which no URL was found.

If a request fails, the error is printed and the script continues with the next brand.

### Checking the dictionary

In order to check whether the dictionary is missing any important words, all queries were run once again without `optional`. Then, about 200 most frequent words from the returned URLs were selected (without the words from the brand names and technical words such as `https`, `www` or `html`) and the list was pasted into an AI assistant with the question which of these words are strictly connected with alcohol and worth adding. The assistant pointed to the word `veviski`. I verified it manually: it is the name of a Turkish website about alcohol. After adding this word to the dictionary, the queries returned more URLs.

### Manual review

The URLs of each brand in the file `review_urls.csv` were checked manually. If at least one URL was not related to alcohol, the word out was written in the column `decision`. The decision concerns the whole brand, so one wrong URL removes the brand from the final list.

Out of 127 brands, one was rejected: `benchmark`. The URL found for this brand was a page of a gaming website, which contains the word `gin` in the address, so it fulfilled the condition with the dictionary.

### Final queries

The script `final_queries.py` takes the queries from `queries.json` for the brands that are in `review_urls.csv` and have an empty column `decision`. Brands without any URLs are not included, as required in the task. The result is saved in `data/kleniec.json`. Below is an example of one entry (the `optional` list is shortened):
```python
{
  "id": "jack daniel's",
  "required": [{"keyword": "jack-daniel", "mode": "c"}],
  "optional": [{"keyword": "vodka", "mode": "m"}, {"keyword": "whisky", "mode": "m"}],
  "optionalThreshold": 1
}
```

## Analysis of the results

The full analysis is available in the notebook `result_analysis.ipynb`. 

### Sources
The source `source4` returned the largest number of URLs (167) and found the largest number of different brands (88). It is followed by `source1` (71 URLs, 45 brands), `source5` (56 URLs, 38 brands) and `source3` (30 URLs, 13 brands). The source `source2` did not return any URLs. This source also has the smallest sample size (about 10,600, while the others have between 460,000 and 1,130,000), which may be an explanation.

![Sources](/images/totalurls.png)

### Length of the name
The longer the name of the brand, the smaller the chance of finding a URL. Among one-word names, 33.2% had at least one URL, among two-word names 8.5%, and among names with three or more words only 1.9%. A possible reason is that all words of a name are joined into one phrase, so the URL has to contain the whole phrase.

![Share](/images/shareofbrands.png)

### Words, brands and domains

The dictionary words that appear in the URLs most often are `whiskey` (43 URLs), `whisky` (42), `veviski` (36), `bourbon` (36) and `cocktails` (26). Most brands have only a few URLs. The highest number is 19, for `jack daniel's`. The most frequent domains are `veviski.com` (36 URLs) and `whiskyliquorstore.com` (19 URLs).

![top5](/images/top5dicwords.png)
![top10](/images/top10brands.png)
![top5d](/images/top5domain.png)

### Queries without the dictionary

To check what the dictionary removes, the queries were run without `optional` for a random sample of 50 brands taken from the brands that had no URLs in the first run. Only 7 of the 50 brands returned any URL, so for the other 43 brands (86%) removing the dictionary did not help. Judging by the addresses, most of the URLs are not related to alcohol. For example, `rabbit hole` returned pages about a TV series (such as https://www.theguardian.com/tv-and-radio/2023/mar/27/tv-review-rabbit-hole), `dingle` returned pages about TV characters and a town in Ireland, `finlandia` returned news about the country Finland, `el mayor` returned Spanish news articles.

Among the returned URLs, only two looked related to alcohol. The first one was found for `bib & tucker`: https://beveragedynamics.com/2022/12/08/bib-tucker-2022-holiday-topper/. It was not found with the dictionary, because none of the words in this address is in the dictionary. 

The second one was found for `dovetail`: https://www.gobourbon.com/bringing-the-heat-barrell-craft-spirits-releases-140-proof-barrel-strength-gold-label-dovetail/.

The experiment shows the trade-off clearly: the dictionary removes a large number of irrelevant URLs, but a small number of correct ones are removed together with them.

## Limitations

Only 127 out of 1069 brands returned any URL, and it is not known how many correct URLs are missed by the queries. There may be many possible reasons, including that the estimator sources may contain too few samples, the condition with the brand name and a dictionary word is strict, the names may be written differently in URLs and names with many words are difficult to match.

## How to run
Run all commands from the project root directory. Create the `data` directory if it does not exist, as the scripts save their output files there.

```python
pip install -r requirements.txt
python scraper.py
python data_preparation.py
python query_generator.py
python query_executor.py
```
After that, open the file `data/review_urls.csv`, write `out` in the column `decision` for the brands with wrong URLs and run:

```python
python final_queries.py
```
